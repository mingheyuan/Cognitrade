# 冻结研究资料多轮读取修复

## 范围

修复六维研究把全部冻结原文放进一次请求、在调用 SDK 前超限的问题。保持固定 UZI 3.9.4、medium/full、gpt-5.6-luna、现有并发和超时、原生研究问题与自审。不得隐式联网、扩大读取到其他 Manifest、改写冻结工件或提交推送。

## 实施

1. 内容寻址只读资料库：完整保存本次已验证的材料化快照及原文，目录分页、字面检索、按偏移读取；每次返回限定大小、完整长度、hash 和原位置，检索无结果不等于事实不存在。
2. Codex SDK 单个研究会话内通过 dynamic tools 多次读取。只接受登记的读取工具；其他工具、权限请求、联网、写文件仍拒绝。隔离持仓和研究组，共用原有排队、超时与取消预算。
3. 首个请求只含研究规则、固定输入身份和资料入口；缓存键绑定整套资料 hash 及读取协议。读取记录与覆盖范围作为宿主审计保存，不混入模型结论或声称全量审阅。
4. 保留旧小输入兼容路径及数据中心采集流程，真实报告通过 Codex 使用新读取链路。原生证据数量和最终自审不放宽。

- 大于 100 万字符资料可从目录检索并读取尾部；所有字符可按偏移恢复，重复正文去重但绑定不丢失。
- 未登记 ID、路径、额外参数、超大读取、跨会话工具及未知工具拒绝；取消和超时会关闭实际会话，不泄漏正文到诊断日志。
- 三组请求大小不随原文总量增长；正文变更使缓存失效；缓存命中保留原读取审计。
- 必要本地回归；真实冻结单股研究探针先验证，然后按结果继续基金 medium/full 报告与回测预检。原生阻断与系统失败分开记录，不制造成功。
