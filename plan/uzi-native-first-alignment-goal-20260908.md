## 2. “对齐原生”的明确边界

### 2.1 本轮必须对齐

- 原生数据及 DimResult 的字段、类型、来源、错误、超时、缺失值语义；同一输入不得被宿主提前补成零值、中性值或非空说明以取得通过。
- 固定 SKILL 的完整 Agent 工作流：真实研究、逐人方法论判断、写回 Agent 产物、原生综合和自审；不能用纯脚本快速模式冒充完整 Agent。
- 原生的计算函数、公式、权重、评级、角色覆盖合并顺序、作战计划和原生检查结果。宿主不能额外重算后仍标为原生原值。
- 原生补证能力：发现来源、读取原文、回答研究问题、提出有依据的字段修订、原生重算。Cognitrade 将业务取数和证据修订放在用户显式启动的数据中心任务，不丢掉这项能力。
- 原生自审逐项结果保持 severity、issue、suggested_fix；不将本地完成度或 PIT 约束混进原生 critical 数量。

### 2.2 必须保留的架构差异

- 数据中心异步采集及历史回补；自动补采/订阅默认关闭。
- 原文落库、按天的可见性、不可变 Bundle/Manifest、输入与引用 hash、来源权限、禁止未来信息。
- 报告只读已固定业务数据，可调用分析模型，但不得隐藏下载新事实。补证产生新版本，旧报告/Manifest 不漂移。
- 阶段级缓存与局部恢复、取消和共同截止，不改回原生可能采用的全量重跑。已有持仓与合格维度继续复用。
- 报告条件回放及真实行情核算属于 Cognitrade 的执行约定，不声称是原生现成回测。继续使用原评级许可和 dashboard.battle_plan，不增加评分阈值、MA 策略或自动再平衡。
- 已修复的安全、持久化和纯展示问题不回滚。例如禁止隐藏业务取数、PIT、防 GB 级快照重复写入和 `/100` 字距修复。

这些差异需要有清单、理由和测试。它们不应改变原生权威业务结果；若确实影响结果，必须记录影响路径，不能仅登记“允许差异”就宣称完全等价。

### 2.3 本轮不做

- 不升级上游到 `650788c` 或其他提交，不调整模型、档位或并发来制造更好的对照。
- 不先修原生的“非多头”误判、PE 分位默认50、汇总残留等固有缺陷再比较。它们先记录为 `known_upstream_issue`。
- 不把原生固定比例作战计划替换成 Agent 买区或自主定价。本轮只核验与准确标识其来源。
- 不为了复现上游而回滚已有安全保护、伪造登录信息/错误、把当前事实填到历史日期。
- 不把含已知实质错误的对照产物宣称为可信投资报告。基准一致与质量合格分开，后续修上游缺陷需要独立版本与复验。
