# A 股研究系统 MVP 方案 + PRD（自进化与认知增强版）

Python + Instructor + Pydantic + taxonomy file + Qdrant client

## 1. 项目定位

这是一个面向个人 / 小团队研究使用的 **A 股智能研究增强与自进化系统**。

它的目标不是做一个黑箱自动选股机器人，而是把：
- 实时行情与财务硬数据
- 新闻 / 公告 / 研报 / KOL 长文资料
- 用户长期偏好与历史研究结论
- 经过市场真实现实（价格与数据）洗涤并自我优化的自进化方法论

组织成一个 **按需触发（Just-In-Time）** 且 **具备认知闭环（Self-Correcting Loop）** 的智能投研工作流，帮助用户高效完成：

1. **个股深度体检**
2. **行业 / 主题聚焦研究**
3. **KOL 逻辑蒸馏与方法论自进化复盘**

本方案的核心架构是：

# **Qdrant Metadata-First Hybrid Retrieval + Mem0 Evolutionary Cognition**

即：
- 检索底座用 Qdrant 承载全量结构化元数据与高价值知识单元。
- 记忆与元认知层用 Mem0 记录用户偏好、KOL 蒸馏维度及 Agent 自身动态迭代的方法论。
- 引入异步“反思与复盘”机制，用真实现实（价格走势与确定性硬数据）对软逻辑（KOL 分析与预测维度）进行清洗与对齐，实现 Agent 方法论的自我优化迭代。

## 2. MVP 范围

### 2.1 本期要做
只做三种核心业务模式：

1. **个股深度体检**：快速摸清个股现状、多空分歧及近期异动。
2. **行业 / 主题聚焦研究**：梳理板块催化剂、核心逻辑链及候选个股核心因果。
3. **KOL 逻辑蒸馏与方法论自进化复盘**：
   - **维度蒸馏与合并**：提取各市场 KOL 的核心分析维度（如净流入、板块热度、宏观政策等）并去重合并。
   - **硬数据清洗与对齐**：根据后验的真实价格和市场走势，验证各分析维度的准确性与胜率，清洗低效噪音。
   - **方法论自我进化**：将验证后的高效分析逻辑沉淀为 Agent 的专属记忆与投资方法论，实现自我迭代。

### 2.2 本期不做
- 全市场自动推荐 / 选股指标全包围
- 高频 / 实时自动交易与自动下单
- 黑箱自动选股与投顾式直接买卖建议
- 复杂回测平台（仅做逻辑与价格对齐的轻量反思）
- 多用户复杂权限系统
- 全量原文粗暴 chunk-first 的传统 RAG

## 3. 产品目标

### 3.1 个股深度体检
用户输入一个股票代码 / 股票名，系统输出：
- 最近行情与异动摘要
- 最近相关新闻 / 公告 / 精选 KOL 观点摘要
- 主要多空逻辑（对齐系统当前最新方法论权重）
- 所属主题 / 赛道
- 关键风险点与胜率评估
- 是否值得继续跟踪及可追溯的证据引用

### 3.2 行业 / 主题聚焦研究
用户输入一个行业 / 主题关键词，系统输出：
- 行业近期催化与新闻主线
- 主题核心逻辑摘要（基于过滤清洗后的高效维度）
- 候选个股列表及每只候选股被提出来的原因
- 当前分歧点、风险点与关键证据引用

### 3.3 方法论自进化（Agent 核心特质）
系统通过运行历史数据的后验复盘，实现：
- 拥有自有的动态“投资方法论一套记忆”。
- 能够辨别哪些 KOL 的哪些维度（如“板块热度” vs “净流入”）在特定市场环境下更具价格解释力。
- 自动根据价格走势复盘并调整前置检索/分析时的特征权重，实现自我进化。

## 4. 系统设计原则

### 4.1 JIT 单次运行与异步反思相结合
- **前台任务**：用户发起一次任务，系统跑一次完整闭环，返回结果，保持轻量高效。
- **后台反思**：定期或异步触发复盘流，拉取历史预测点与真实价格走势进行对齐，内化为长期方法论记忆。

### 4.2 数据先筛，LLM 后审；硬数据验软逻辑
- 确定性数据筛选（行情、基本面）仍由 Python 数据逻辑与 API 负责。
- LLM 负责整合信息、归纳逻辑、解释原因以及**作为复盘主体去对比“预测逻辑”与“真实走势”的偏差**。
- 用绝对客观的**价格与财务硬数据**，去检验和清洗 KOL 的**主观软逻辑**。

### 4.3 Memory 与 Retrieval 分层
- **Mem0（自进化认知层）**：存用户偏好、KOL 蒸馏合并后的标准维度池、以及 **Agent 进化中的动态方法论与权重规则**。
- **Qdrant Retrieval Layer（证据检索层）**：承载原始材料、结构化切分、metadata 检索、精排候选集。
- **Raw Sources（原始资料层）**：存不可篡改的原始新闻、公告、研报、KOL 长文原文。

### 4.4 先做研究增强，不做自动决策
系统定位是 **研究外脑 / 认知进化增强系统**，不直接决定买卖，而是帮用户洗净全网噪音，输出高纯度、进化后的深度投研逻辑。

## 6. 核心组件与分工

### 6.1 LangGraph（调度骨架）
负责编排数据拉取、记忆召回、证据检索、反思对齐与分析输出，控制状态流转。
本期保留三个核心路由：
- `stock_check`：个股深度体检
- `sector_research`：行业聚焦研究
- `methodology_evolution`：方法论复盘与自进化流

### 6.2 数据网关层（Python APIs）
- **行情数据**：日线/分钟线、成交额、换手率、涨跌幅、成交量变化（AkShare 入口）。
- **基本面数据**：市值、PE/PB、利润增速、ROE、毛利率、财报摘要。
- **新闻与文本源**：快讯、公司公告、研报、**KOL 长文/观点抓取源**。
- **验证硬数据**：提供 T+N 时间窗口的真实股价走势、真实板块净流入数据，用于后验洗数据。

### 6.3 Mem0（自进化认知层 - 升级版）
Mem0 在本系统中充当 **Agent 的大脑记忆与元认知中心**。
1. **用户偏好**：不碰 ST、偏好赛道、风险偏好、最大回撤容忍度。
2. **动态维度池**：从各大市场 KOL 处蒸馏、合并去重后的标准分析维度表（如：资金面-净流入、情绪面-板块热度、基本面-宏观政策等）。
3. **Agent 自有方法论（Evolutionary Methodology）**：
   - 记录经过价格复盘验证后的维度胜率评估（例如：“在当前震荡市中，情绪面-板块热度维度的解释力已下降至 30%，资金面-个股净流入异动解释力上升至 75%”）。
   - 包含当前版本的方法论过滤偏好，用于指导前台检索。

### 6.4 Raw Sources（原始资料层）
包含新闻全文、公司公告、券商研报、**KOL 长文原文**、API 原始返回快照。不做任何模型改写，仅作为最终的证据链条与追溯来源。

## 7. Qdrant Retrieval Layer 设计

Qdrant 在本系统里不是“纯向量库”，而是：**带强元数据（Metadata）、结构化切分、混合召回和轻量重排的检索底座**。

### 7.1 核心思想
1. 先按结构切分（拒绝暴力 Token 乱切，以页/章节/一条 KOL 观点摘要为一个 Logical Block）。
2. 先按元数据（Metadata）缩窄搜索空间。
3. 再做关键词/标题定位。
4. 结合 Mem0 当前进化出的方法论维度权重，进行轻量语义检索与精排（Semantic Rerank）。

### 7.2 扩展元数据（Metadata）
至少包含：
- `stock_code` / `stock_name` / `sector` / `theme`
- `source_type`（news / filing / report / **kol** / note）
- `distilled_dimensions`（关联此文本涉及的蒸馏维度标签，如 `["资金面-净流入", "情绪面-板块热度"]`）
- `publish_time` / `time_window`
- `document_title` / `document_id`

## 8. 核心工作流设计（包含自进化机制）

### 8.1 个股深度体检工作流 (`stock_check`)
1. **输入**：股票代码 / 股票名称。
2. **拉取数据**：拉取个股实时行情、基本面指标、近期新闻公告。
3. **调取记忆**：从 Mem0 读取用户偏好，并读取 **Agent 当前最高胜率的方法论维度偏好**。
4. **检索证据**：在 Qdrant 中根据 `stock_code` 及方法论推荐的 `distilled_dimensions` 进行强 filter 过滤，召回核心 logical block。
5. **LLM 综合分析**：LLM 结合行情与高权重维度的证据链，输出深度个股体检报告。
6. **异步记录**：将本次个股的关键多空逻辑切片和 LLM 预测点打上时间戳，异步写入待复盘池。

### 8.2 行业聚焦研究工作流 (`sector_research`)
1. **输入**：行业 / 主题关键词。
2. **拉取数据**：拉取行业催化剂新闻、板块成分股、重点个股行情。
3. **调取记忆**：结合 Mem0 调取该行业长期逻辑及当前市场环境下最有效的特征维度。
4. **检索证据**：Qdrant 过滤相关 `sector` 与高质量 KOL 沉淀出的逻辑卡片。
5. **输出结构**：行业主线、核心逻辑链、候选股列表及被筛出原因、分歧点与风险点。

### 8.3 KOL 逻辑蒸馏与方法论自进化工作流 (`methodology_evolution`)

#### 第一步：蒸馏与合并
1. **输入**：全网抓取的各市场 KOL 长文、深度观点。
2. **逻辑蒸馏（Node: Distill_KOL_Logic）**：
   - LLM 强制剔除情绪化水话与模棱两可的修饰词。
   - 抽取出核心分析因子与因果关系（例如：“因为主力资金净流入且宏观政策支持，所以看好大科技板块”）。
3. **维度合并（Node: Merge_Dimensions）**：
   - 将含义相近的表述统一对齐至标准维度。例如，将“机构抱团”“大单买入”“净流入”合并为标准维度标签：`资金面-净流入`。
   - 将提炼后的标准维度与原始文本关联，作为 payload 写入 Qdrant。

#### 第二步：洗数据与价格对齐
1. **后验触发**：当记录的预测或分析达到设定的观察周期（如 T+5 或 T+20 交易日）时，触发对齐节点。
2. **硬数据调取**：Python 数据网关调用 AkShare 拉取该个股/板块在 T+N 期间的真实价格走势、实际换手率及财务异动。
3. **洗涤与校验（Node: Verification_Calibrator）**：
   - LLM 或规则脚本将“当时分析采用的维度”与“真实走势结果”进行对比。
   - **判定逻辑**：如果系统此前高频采信的某 KOL 维度（如“宏观政策”）连续多次在观察窗口内与真实股价走势毫无相关性，甚至发生背离，则该维度的“信噪比得分”被调低。
   - 清洗低效数据，过滤掉与真实市场反馈不一致的“伪逻辑”与噪音。

#### 第三步：输出新结论，实现自我迭代
1. **方法论内化（Node: Meta_Cognition_Update）**：
   - 根据维度清洗与胜率计算结果，LLM 生成一份**《方法论复盘与元认知迭代报告》**。
   - 自动在 Mem0 中更新 Agent 自身的“一套记忆”与方法论模型（例如：“在缩量市场下，将‘情绪面-板块热度’前置检索权重从 0.8 降至 0.3，将‘基本面-出海增速’权重调高至 0.85”）。
2. **演进效果**：当下一次执行“个股体检”或“行业研究”时，Agent 已经自带了这套自我优化后的新方法论，优先聚焦并召回最具市场解释力的维度，实现认知闭环。

## 9. LangGraph 节点编排建议

```text
[methodology_evolution_flow]
load_kol_and_history_predictions
  ↓
distill_kol_logic        -> 提炼核心分析因子
  ↓
merge_dimensions         -> 合并去重，建立标准维度池
  ↓
fetch_post_market_data   -> 拉取 T+N 真实价格与硬数据
  ↓
verification_calibrator  -> 硬数据验软逻辑，清洗低效维度，计算胜率
  ↓
meta_cognition_update    -> 更新 Mem0 中的 Agent 自有方法论记忆
```

## 10. 数据写回策略

### 10.1 写回 Mem0
- **严控噪音**：只写回经过价格复盘验证、跨任务可复用的研究结论。
- **写回 Agent 自进化方法论**：记录带有版本号的认知演进状态（如 `Methodology_v1.2_2026Q2`），包含当前高胜率的维度列表和前置过滤规则。

### 10.2 写回 Qdrant 辅助层
- 写回清洗去重后的 KOL 逻辑摘要卡片。
- 更新 Logical Block 元数据中的 `distilled_dimensions` 标签及胜率关联分。

### 10.3 不写回
- 与市场真实价格完全背离的垃圾预测及无价值快讯。
- 无法复用的一时情绪化探讨与低质量舆情噪音。

## 11. MVP 成功标准

1. **个股与行业报告质量**：生成的报告逻辑链条清晰，不流于表面水话，能精准命中多空分歧。
2. **维度蒸馏能力**：能够把大段的 KOL 长文精准脱水，转化为结构化的标准维度标签。
3. **认知闭环跑通**：系统能成功将一笔“历史多空分析”与“后验价格走势”对齐，并完成至少一次自动调低无效维度权重、更新 Mem0 记忆的方法论进化闭环。
4. **硬数据约束**：系统在任何时候均以价格和财务硬数据为终极检验标准，避免 LLM 陷入纯文本的自我循环与脑补。
