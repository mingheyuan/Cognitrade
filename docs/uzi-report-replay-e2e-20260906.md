## 真实测试发现并追加修复的问题

1. 验收脚本把业务 Finance 路由误发到 V1：改为 Finance V2、run/持仓批次 V1，保留首次 404 审计。
2. 基金列表有 `portfolio_summary`，详情 API 却漏字段：统一使用同一状态投影，避免脚本误判没有可重试槽。
3. `partial` 槽被前端当作未结算活动槽：部分完成与严格可用分开，活动数只取真实运行状态，研究归档单列。
4. 买入条件触发时就消费计划：改为首次真实成交后消费；撤单不变相缩短许可，仍不允许自动补仓。
5. 原生报告价格被无条件标成未复权：改为核验冻结 `0_basic` 原价锚点、日期、来源/hash，与原生三价一致。
6. 历史政策仍会调用无日期参数的当前新闻流：有指定历史截止日时跳过该流，只使用日期限定路径及独立原文归档。
7. 父批次内联完整 Manifest 导致反复读写约 85 MB：输入只保存一次，批次状态保留引用和 hash。
8. 定向重试时用 55 槽重试范围覆盖全部 65 槽缺口：保留完整槽位投影，避免运行中虚增完整度。
9. 全部股票计划 BLOCKED 也能生成现金回测：预检及执行器现在要求实际存在合法、价格已核验的计划；合法 WATCH 仍允许真实零成交。
10. 无原生输出被误称“报告价与冻结价冲突”：明确为尚未核验，不生成虚假的 `0_basic` 补采建议。
11. 心跳、详情或进度持久化异常提前释放父任务：先取消并等子批次真实退出，再抛原异常，不重叠恢复。
12. `4_peers`、`14_moat`、`18_trap` 只取得素材、没有最终历史派生字段，却被标为来源故障：区分派生未完成、历史候选不足与真实网络/权限失败。

上述修复不改变原生报告结论、价格或 critical 等级。
