# UZI 冻结报告与条件回放 V2

本轮固定 UZI 3.9.4 / `b3665e85b8666477038e11157d8e8feb0e006b76`，不升级上游。
执行方案见 [修复执行方案](../plan/uzi-report-replay-e2e-repair-plan.md)。本文件说明实现契约，不代表真实报告已经通过自审或已经发生交易。

## 职责与使用顺序

1. 在数据中心显式创建当天采集或历史补缺任务。完整采集还会归档研究原文；单股、单维重试保留定向范围。自动补采和订阅不因本轮修复而开启。
2. 分别查看结构化槽位完整度、研究原文归档进度、数据冻结候选。确认冻结仅发布数据版本，不代表最终报告可交付。
3. 从基金 Bundle 创建报告任务；基金 Bundle 决定持仓、顺序、披露权重及来源，不再要求先跑旧 `fund_snapshot`。未指定 Bundle 时，任务开始解析目标日期的最新合格版本并立即固定。
4. 正式报告采用完整 Agent 工作流，原生机械检查使用实际 `lite / medium / deep` 档位。数据与研究引用缺口交给 Agent 按原生规则研判，不由宿主在启动前额外拒绝；仍可作为手动补采提示，不在报告阶段联网补数据。冻结 hash、来源权限、撤销状态、固定执行版本与 PIT 合法性仍是独立安全门槛。
5. 选择 V2 报告条件回放策略，先在数据中心采集回测区间的未复权行情及价格口径证明，再运行回测。行情不要求采齐全部 22 维，也不会进入较早的报告输入。

历史报告属于“基于当时可见资料的回溯生成”，不是当日真实发布记录。

## 不同状态不要混用

| 状态 | 含义 |
| --- | --- |
| 严格完整度 | 有多少数据槽严格合格；降级缺口单列 |
| 数据可冻结 | 可以确认发布不可变数据版本，不承诺报告通过 |
| 报告输入安全校验 | 固定数据的权限、hash、撤销状态、版本和 PIT 合法性；失败可阻止启动 |
| 研究输入提示 | `data_issues` / `evidence_gaps` 提示数据及引用缺口，交由完整 Agent 处理；不单独禁止启动，也不承诺最终通过 |
| 最终原生自审 | Agent 已完成研判后，原生 UZI 是否允许交付 |

输入安全阻断、模型/系统失败、原生自审拒绝、人工取消分别记录。研究输入提示不是新增的报告交付门禁，原生评分权重与最终自审规则不因缺口提示而改写。回放完成且零成交也是独立结果，不能用全现金结果冒充真实交易链路通过。

## 可复现输入

新 Manifest 固定基金与股票 Bundle、快照 hash、证据 ID/正文 hash/引用关系，以及投影、原生提交、档位、完整工作流、模型及提示词版本。新增证据不会自动进入旧 Manifest，分析缓存也包含该固定证据集合。

正文/PDF 按内容 hash 归档；搜索结果只用于发现来源。历史原文必须有发布时间及版本依据，首页、列表页、接口文档和只有旧日期的 URL 不能充当研究原文。浏览器发现的链接仍须通过正文和历史版本校验。

旧 Manifest 保留旧投影；无法证明完整历史证据集合的记录明确标示复现限制。已冻结 Bundle 不原地修改，补采产生新快照、新 Manifest 和报告修订。恢复不重新选择“最新”输入，也不静默切换模型或提示词版本。

## V2 执行约定

以下是 Cognitrade 的明确回放约定，不宣称是 UZI 原生现成订单规则：

- 读取原始评级，“值得重仓／可以蹲一蹲／可以蹲（偏弱）”允许新开仓；其他评级不新买，也不额外强制卖出。
- 直接读取最终结构化报告的 `synthesis.dashboard.battle_plan`；保存原值、字段路径、原生报告 artifact/hash 和提取版本，不让第二个模型解释 HTML。
- 不再叠加 MA5/MA20、旧分数阈值或基金综合评分。价位缺失/矛盾、报告未允许交付时明确不可执行。
- 单股预算按基金原始披露权重并受单股上限约束，不归一化。仅一次性使用该预算的 50% 首批建仓，包含费用；不自动加仓、再平衡或满仓。
- 未成交撤单不消费计划；有效期内可在后续收盘重新触发，不能同一开盘追单。首次真实成交后才记为已消费，之后不再重复首批。
- D 日报告从下一交易日起按收盘判断：`止损 < 收盘 <= 入场价` 才触发入场，次一交易日真实开盘成交。入场价不是成交限价；没有真实开盘价就没有虚构成交。待买开盘触及或越过止损/目标时取消买单，退出仍用实际开盘价。
- 新开仓许可含生效日共三个交易日，成交前再次检查。第三日收盘触发、第四日开盘已过期，不成交。
- 新报告替换未入场计划；已有仓位锁定建仓报告的止损/目标，直到平仓。缺报告、负向新评级或许可过期不会删除退出保护。
- 保留股票池、现金、整手、费用及 T+1。报告失败不能删除持仓或行情需求。日线模型不模拟盘中触价，不宣称实盘级成交精度。
- 仅支持人民币 A 股未复权实际价格。公司行动/复权因子必须有独立字段查询证明；无法可靠处理的除权区间明确拒绝准确回放。
- 报告三价还需与冻结 `0_basic` 的实际价格锚点、日期、来源及 hash 一致。`2_kline` 的前复权技术分析不能代替原价证明；缺证明的计划不可执行，并返回该日 `0_basic` 补采范围。

旧 StrategyDocument V1 的序列化/hash 和旧均线策略保留；历史信号不原地转换。V2 暂不接纸面委托，防止意外落入旧执行规则。

## 接口与迁移

- `POST /finance/report-jobs` 及估算入口接受可选 `fund_bundle_id`；显式 ID 只适用于单日，区间逐日固定。
- V2 新信号增加可空 `execution_plan_json`。已有数据库须执行 Alembic `upgrade head`，本轮迁移为 `20260906_0006`；`create_all()` 不能代替迁移，旧行保持 NULL。
- 回测 create/preflight 接受 `market_data_manifest_hash`；重放只读取已固定、归属及 hash 均通过校验的行情集合。未提供时只从落库行情生成清单，缺失返回补采范围。
- 活跃批次 ID 在创建后即持久化。排队、请求、退避共用截止时间，瞬时错误最多两次阶段重试；取消要等待实际请求退出，数据缺口和无进展不自动整股重跑。

行情 Manifest 仅固定价格集合，不替代报告/信号输入集合。比较两次运行是否精确一致时，
还需确认报告修订、信号 hash、策略版本和整体 `input_hash` 均相同；新增报告后不能仅凭
相同行情 hash 声称整次回放已复现。日线模型不覆盖盘中路径、滑点、涨跌停及成交量约束。

## 真实验收入口

`scripts/run_uzi_report_e2e.py` 是显式、可恢复的真实 API 验收脚本；不会修改信号制造成交。使用已配置 API token，不把凭证写入结果。

```bash
.venv/bin/python scripts/run_uzi_report_e2e.py --execute \
  --output workspace/reports/e2e-uzi-20260906 --stage all
```

默认样本为基金 `020464 / 2026-09-02 / medium`，回测到 `2026-09-04`；先做 `688012.SH` 当天行情/事件小探针。周末保留真实最近交易日，不虚构周日行情。结果保存阶段请求、任务 ID、来源、冻结 hash 和独立的链路/原生报告/回放状态。真实阻断不会通过降低门禁或改造测试数据隐藏。

这个短区间最早只能在 9 月 4 日买入，因此即使真实买单成交，也不能据此宣称真实卖出、
止损或完整持有周期已验证；这些边界另用明确标注的确定性测试覆盖。
