# UZI 报告预检对齐修复（2026-09-06）

## 结论与范围

本次修复报告**启动预检**额外加严的问题，固定 UZI 3.9.4 提交
`b3665e85b8666477038e11157d8e8feb0e006b76`，不升级上游。
数据中心负责冻结证据，Agent 负责分析，最终自审决定是否允许交付。
移除错误的启动限制，不代表数据已经补齐，也不代表所有报告都能通过。

## 对齐依据

- 原生 `scripts/run_real_test.py` 的 stage1 写入数据缺口并继续交给 Agent，不因这些缺口直接退出。
- 原生 `skill/SKILL.md` 及 `skill/references/task2.5-qualitative-deep-dive.md`
  要求六维 Agent **输出**每维至少两条带 URL 的证据，不是要求启动前有两个不同 URL。
- 同一文档可以支持两个不同事实；重复同一事实不能凑数。无来源的未知项必须说明，
  但没有 URL 的缺口披露不能替代最终要求的引用证据。
- 原生 `scripts/assemble_report.py` 在分析后执行自审，critical 阻止交付；本次不修改这个红线。

## 修复内容

| 层次 | 修复后行为 |
| --- | --- |
| 报告入口 | 数据问题和研究引用缺口作为诊断传给 Agent，不再提前拒绝模型分析 |
| 六维研究 | 先执行三组 Agent，按真实输出的证据条目检查；同 URL 不同 finding 可以分别引用 |
| 未知事实 | 保留具体缺口；不编造 URL、日期或事实，无 URL 的说明不计入有效证据数 |
| 原始结果投影 | 新 v3 保留实际 `data/error/_timeout/source`，不因本地 outcome 清空数据，不伪造原生 error |
| 历史重放 | v1/v2 规则保留；旧预检只在读取时重解释，原工件、Manifest 和 hash 不改写 |
| 输入安全 | 权限、hash、撤销、执行版本和 PIT 合法性保持独立硬校验 |
| 恢复与展示 | 有研究输入提示不等于“预检失败”；数据可冻结不等于报告可交付 |

最终输入不足仍可能导致 Agent 输出不完整或原生自审失败。用户可手动启动数据中心补采，
产生新数据版本和报告修订；报告阶段不隐藏联网补数，自动采集开关保持不变。
