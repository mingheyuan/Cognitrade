**问题证据**：拓荆科技 `688072.SH`，运行 `01M2HTG40DSMBNPQV44Z04W0GM`，`qualitative_B · Industry-Events` 报 `qualitative_ungrounded_url`。本地适配器把巨潮 API 文档页、统计入口页加入 `historical_evidence`，模型沿用后又被本地 `allowed_urls` 校验拒绝。规范化后请求仅剩 API 根地址，无法作为有效原文归档。

**修复范围**：

- 区分结构化接口数据的溯源、研究原文及检索／接口入口，不把三者混成同一种“文档证据”。
- 结构化事实保留实际 provider、查询参数／日期、快照及响应 hash，不为了满足 URL 字段而虚挂无关原文；入口保留为来源说明或检索线索。
- 对齐原生“允许研究过程中补充核实资料”的逻辑，冻结输入作为版本及事后审计依据，不能把初始 URL 目录当作永久研究边界。
- 新资料经允许的补采／核实流程形成新证据及输入修订；保留旧 Manifest，不静默改写历史报告。
- 报告缺引用时准确区分“已有真实接口数据但溯源表示不兼容”“缺有效原文”“未经核实的新线索”。

**验收标准**：

- 接口入口不会被当作文章正文；真实接口数据也不会仅因没有文章 URL 被误判成完全无数据。
- 明确的无效根地址不会生成一个必然无效、反复重试的正文补采循环。
- 经核实新增的有效来源可进入报告修订；未核实线索不能直接冒充证据。
- 拓荆不再因本地输入／校验语义冲突失败；若原文确实缺失，应保留具体原因，不降低原生证据要求制造成功。

- 日期、来源或字段绑定冲突可被必要回归发现；有效的同一文档多条不同证据仍允许使用。
- 不额外要求所有数值必须有独立文章，不靠虚构链接或降低原生要求补齐数量。
