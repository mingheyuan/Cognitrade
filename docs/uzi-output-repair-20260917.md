## 实现

1. **保守识别完全周期性输出**：仅对逐维评论及 `narrative_core` 开启。
   单条未完成的最终回答，在连续 4096 字符窗口内出现周期不超过 1024 字符的完全重复时，
   将其归为 `llm_output_repetition`。跨消息、commentary、正常长文本不按此规则拒绝。
   保留有界内存窗口，日志只记录阶段、长度、周期、hash 和终止信息，不记录正文、推理或凭据。
2. **只修复受影响阶段一次**：中断并确认旧 SDK 运行时退出后，从同一证据重新生成当前完整 JSON。
   不接受截断文本；不修改结论；第二次仍重复就明确失败，外层不重新跑整只股票。
   上游瞬时错误仍最多两次退避，两个重试计数独立但共享原截止时间。
   取消、预算耗尽和进程退出未确认均禁止启动新请求。
3. **前置已有批次约束**：维度请求的 JSON Schema 固定本批条数、允许的维度 ID 及缺口数量。
   原来的 Pydantic、维度成员及引用路径校验继续执行；没有新增正文长度或辩论轮数上限。
4. **完整传递新失败类型**：工件 Schema、恢复判定、进度和基金报告错误提示同步支持重复输出，
   不把它误报成数据采集缺口；其他自审问题继续保留。

重复保护属于本地执行可用性措施，**不是原生 UZI 的新增交付门禁**。
使用 OpenAI Docs 核对 SDK 事件与中断语义后，保留停止时快照、清理阶段终态和运行时退出确认，
不把中断后的事件当作停止之前已生成有效报告的证据。
协议依据：[Codex App Server 官方说明](https://learn.chatgpt.com/docs/app-server)。
