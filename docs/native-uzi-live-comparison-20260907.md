# 原生 UZI 实跑与 Cognitrade E2E 对照（2026-09-07）

## 结论

**原生也有问题，不能把 Cognitrade 本轮失败全部归咎于模型，也不能把原生自检通过等同于报告完全正确。**

本次重新从 GitHub 克隆上游，未修改其源码，做了两种不同实验：

1. 将 Cognitrade 最近一次十股 E2E 的原始最终工件交给新下载的原生 Python 自检：**十股仍全部不通过**。共同问题是第 19 维空数据；另外九股还缺 Agent 分析。海光的本地六维证据边界 critical 则不出现在原生 Python 检查中。
2. 按原生 SKILL 的完整 Agent 路径重新研究海光信息 `688041.SH`：真实采集、浏览器兜底、三组研究 Agent、四组共 66 人方法论模拟、原生综合与 HTML 组装。**HTML 生成成功，原生自检 0 critical、0 warning**；但实际数据、汇总、作战计划和渲染仍有缺陷，因此只作为诊断工件，**不作为可交易报告交付**。

最重要的架构结论：原生完整 Agent 的价值在于“看见缺口后自主查原文并研判”，不是所有采集脚本天生完整。Cognitrade 应将这项补证能力落实到数据中心，再让报告只读固定证据；不能通过复制上游默认值或减少检查假装问题消失。

### Agent 确实补到了什么

- 公司正式半年报确认行业为集成电路设计、主营 CPU/DCU，不是“综合”。

## 3. 已复现的原生问题

### A. 数据取回不等于证据正确

1. **空行业导致查询漂移。** 原生 basic 的行业为 null，行业/政策等查询落到“综合”，而不是围绕海光主营。
2. **混入其他公司的证据。** `14_moat.data.scale` 使用北方华创设备说明，不能证明海光规模壁垒。
3. **公司名拆词误匹配。** 舆情把“信息”当关键词，命中“哪些信息值得关注”的无关知乎热榜；同时有效舆情标志为 false。
4. **空结果被解释成安全。** 第 18 维 0 条证据、0/8 命中，却展示绿色安全，不能据此证明排雷完整。
5. **第 19 维非空信封掩盖空持仓。** HTTP 200、登录提示、空列表、同花顺登录说明让 `data` 非空，原生机械检查通过；没有获取真实比赛/雪球组合持仓。
6. **日期陈旧。** 治理质押记录实际为 2024-09-06，不能当 2026-09-07 最新状态。

### B. 确定性代码和模板问题，不是 LLM 过期

| 问题 | 本次真实输入 → 输出 | 影响 |
| --- | --- | --- |
| 多头误判 | `ma_align="非多头"` → `ma_bull_aligned=true`；原始指标是 false | 原生用子串包含判断，污染技术规则 |
| 缺失估值分位补中位数 | `pe_quantile="—"` → `pe_quantile_5y=50` | 把没有历史数据变成看似精确的估值证据 |
| 行业词表遗漏 | 集成电路设计/CPU/DCU未匹配部分 AI 字面词表 | 评委骨架称不在算力链，Agent需据原文纠正 |
| 假共识基准 | 研究模板用实际值×0.95生成“预期” | 输出营收和利润均超预期约5.3%，不是取得真实市场一致预期 |
| 缺数据变经营结论 | 市占率/行业增速缺失被置0 → BCG `Dog` | 给出收缩建议，但基础数据并不支持该判断 |
| 不合理情景下界 | 年化波动66% → 无杠杆股票最坏情景收益率-132% | 固定倍数正态式场景未处理价格下界 |

本轮未修上游代码；Agent 在评论及结论中拒绝沿用这些错误，不代表原生派生表格已经被修复。

### C. 评委更新后，汇总没有完整更新

66 人实际逐人结果：5 看多、19 中性、15 看空、27 跳过。包含两名 short mandate，按原生多头口径剔除后为 **37 名活跃多头评委：5 多、19 中、13 空**。

但原生 panel 的汇总仍保留规则骨架：41 名活跃多头、5 多、14 中、22 空、23 跳过，共识 32.5。Stage 2 又按更新后个人数据计算风格共识 42.1，并输出综合分 54.1；派系汇总等字段仍沿用旧结果。不能把这些不同计算口径混为一个已同步状态。

风格加权还将两名 short mandate 算入39名活跃评委，而多头投票口径应为37名；这个口径差异也需明确处理，不能只重算一个总分。

本次已按 SKILL 先把个人意见手工合并写回 panel，仍观察到旧聚合残留，**不是漏做个人写回造成的假问题**。

更严重的是，旧 short 汇总里“审计有保留意见”的规则判词仍出现在实际 HTML；本次没有相应审计意见事实证据，Agent 已拒绝该断言，不能将这段残留模板当作对公司的事实描述。

### E. 报告阶段仍会联网，且有隐性放大

`generate_synthesis → detect_style → detect_quant_signal` 会读取基金的前十大持仓。本次输入有 751 条基金经理/基金记录，非空大输入不受 `max_funds=80` 切片限制；该参数仅用于输入太小时自动扩大样本。运行时观察到活跃 TCP 连接和 `.cache/_quant` 持续写入，Stage 2 前段尚未生成 synthesis。

查询年份还硬编码为 `2025`。这与“报告只读冻结数据、按报告日可见资料研判”的目标不同。Stage 2 总耗时 237.953 秒包含这部分联网以及后续渲染，不能全部算 LLM 或 HTML 耗时。

### F. 自检为零问题，但渲染仍需实际验证

实际 Playwright 打开生成的 standalone，而非仅检查文件存在：

- 66 席及评论存在，桌面/手机无 console error、pageerror、坏图或未替换模板标记。
- 评分卡 `/100` 字符挤叠，复现了早期截图中的同类表现。
- 390px 手机视口仍出现横向溢出，溢出元素在 UPSIDE 区域。
- 实际页面评委统计仍展示旧汇总。
- 独立战报 PNG 导航等待 load 超时 30 秒；主 HTML 和分享卡已成功，不能把附加图片失败说成整份报告失败。

具体样式原因：`/100` 在桌面26px字号下继承了 -9.6px 字距，手机18px下继承 -6.6px 字距；手机 UPSIDE 单行 flex 使页面实际宽度达到428px，比390px视口溢出38px。最终稳定显示54分；入视口900ms动画期间的53/45等中间数字不是评分算法错误。

## 4. 对最近 Cognitrade E2E 失败的解释

不能只用一个“LLM 失败”概括，也不能说“只要放松预检即可”。应分开记录：

1. **执行失败：** 原 E2E 九股没有完整 Agent 分析，原生也会拒绝缺分析的交付；仍需解决项目模型排队、请求/阶段失败与恢复问题。本次换成 Codex Agent 并不验证原模型网关可靠性。
2. **同输入数据缺口：** 十股第 19 维空数据在原生机械自检也会阻断。今天拉到登录元数据，不等于补齐历史实盘记录。
3. **本地额外检查：** 海光的六维证据 critical 确实超出原生 Python 自检，但完整 SKILL 仍要求研究。应准确区分采集证据不足、Agent研究未完成和原生可交付检查。
4. **采集/补证能力缺口：** Agent 真实找到了原来结构化采集没提供的官方原文和成本细节，证明其中一些内容可以补，不应过早一刀切降级。
5. **上游自身缺陷：** 固定价格模板、旧汇总、错误默认值、隐式联网和渲染问题需要独立质量保障，照搬原生不能自动解决。

## 5. 建议的后续修复顺序（本轮未实施）

1. 先修报告信号的权威来源与溯源：区别 Agent 条件、原生模板条件、执行约定，避免给回测传递来源不实的计划。
2. 补齐数据中心原文采集和证据归档，保留搜索/浏览器的相关性、时间与失败原因；报告阶段禁止隐藏业务取数。
3. 统一个人评审、票数、派系、short/long及共识的单一投影，并回归模型覆盖后的真实HTML。
4. 修复缺失值不当填0/50、多头字符串误判和行业/公司证据串用，明确未取得与无事件/安全的区别。
5. 单独验证原 E2E 模型接口与限流/超时/恢复；不能把本次原生另一模型的成功当作网关已恢复。
6. 修复评分卡、手机溢出与附加图片超时；必要回归本地执行，全面回归交 GitHub Actions。
